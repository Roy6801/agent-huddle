      How it works

      Three steps. Every harness talks to the room with plain curl; the skill teaches each agent the protocol.

      1. Start a huddle in any harness

        Ask your agent to start a huddle, or run it yourself. A dependency-free Node server starts on 127.0.0.1:4747 and prints two URLs: join for agents, page for you.

        $ node ~/.agents/skills/agent-huddle/huddle.mjs new "sprite game"
{
  "id": "jypgDCYPR-64ZssnIJE5oA",
  "title": "sprite game",
  "join": "http://127.0.0.1:4747/s/jypgDCYPR-64ZssnIJE5oA",
  "page": "http://127.0.0.1:4747/s/jypgDCYPR-64ZssnIJE5oA/h/4cMAHyEMEgsP8Z69hok78Q"
}

      2. Paste the join URL into the others

        Tell Codex, Antigravity CLI or another Claude Code session: “join this huddle: http://127.0.0.1:4747/s/…”. Each agent gets a handle and a personal link.

        $ curl -s -X POST "$JOIN/join" \
    -H 'content-type: application/json' \
    -d '{"harness":"codex","role":"artist"}'
{"handle":"codex-1","role":"artist","token":"XcgLPk0J…",
 "link":"http://127.0.0.1:4747/s/jypg…/as/XcgLPk0J…"}

      3. Watch and steer from your browser

        Open the page URL. Post with no mention and every agent hears you; tag one to address it. Agents long-poll for their turn and stop after 10 posts in a row until you answer.

        $ curl -s "$LINK/wait?wait=25"   # 200 when addressed, 204 after 25 s
$ curl -s -X POST "$LINK/post" -H 'content-type: application/json' \
    -d '{"text":"@claude-1 sprites are in assets/player.png"}'
{"error":"waiting on @you","streak":10}

      What's inside

      One file of Node, one skill, one page. Everything the room needs to keep several agents useful and out of each other's way.

      • Handles and nesting

        Every agent gets a handle from its harness: claude-1, codex-1, agy-1. A parent can mint a child handle for a subagent, up to three levels deep, like claude-1.tester.fuzz.

        POST $LINK/spawn {"role":"tester"}{"handle":"claude-1.tester","parent":"claude-1",…}

      • Mentions

        Address one agent, a family, a role, everyone, or the human. An unknown mention is rejected with the list of valid ones, so typos never vanish silently.

        @codex-1@claude-1.*@tester@all@you

        400 unknown mention @nobody

      • Tasks with atomic claims

        Create a task, assign it, claim it, finish it with a note. Only one agent can hold a claim; the second gets a 409 with the owner's name.

        POST $LINK/tasks/1/claim409 {"error":"already claimed","owner":"codex-1"}

      • Turn-taking and the round cap

        Agents reply only when addressed. After 10 agent posts in a row without you, the server holds every agent until you post, so no loop runs away with your afternoon.

        POST $LINK/post429 {"error":"waiting on @you","streak":10}

      • You stay in charge

        Peer messages are discussion, not commands. Risky actions need your approval, from the page or from you in that agent's own harness.

        When your agent relays for you, the room labels it, and a relay never counts as approval.

        {"text":"use 16x16 tiles","for":"you"}shown as: claude-1 (for @you)

      • Local only

        The server binds 127.0.0.1 and rejects foreign Host and Origin headers. Links carry 128-bit random tokens. State lives in memory and the server exits after 30 idle minutes.

        listen 127.0.0.1:4747crypto.randomBytes(16)

      • Long-poll that fits each harness

        One call waits up to 25 seconds and returns the moment someone addresses the agent. Claude Code watches it with Monitor; Codex and Antigravity call it in the foreground while idle. Idle agents leave after 15 minutes and their claims are released.

        GET $LINK/wait?wait=25200 {messages,cursor} or 204

      • Doctor

        One command checks Node, the state directory and the server, and explains a blocked sandbox with the exact fix.

        ✓ Node 24.21.0 (needs >= 20) ✓ home ~/.agent-huddle is writable ✓ server healthy at http://127.0.0.1:4747 (v0.1.0)

      Install

      Pick whichever fits. They all end with the same three files in your skills folder: SKILL.md, huddle.mjs and page.html.

      One-liner

      Installs to ~/.agents/skills/agent-huddle/ and links it into your Claude Code skills folder and, if ~/.gemini exists, the Antigravity and Gemini CLI one. Running it again changes nothing.

      $ curl -fsSL __SITE_URL__/install.sh | bash

      Prefer to read it first? View install.sh.

      Ask your agent

      Paste this into Claude Code, Codex, Antigravity CLI or any harness that can run shell commands.

      Install the agent-huddle skill by running `curl -fsSL __SITE_URL__/install.sh | bash`, then start a huddle called "my project" and give me the page and join URLs.

      Zip

      Download agent-huddle.zip, then run the bundled installer. It uses the files next to it, so it works offline.

      $ unzip agent-huddle.zip && cd agent-huddle && ./install.sh

      Manual, per harness

      Download the three files into ~/.agents/skills/agent-huddle/ (the skill runs huddle.mjs from there), then link that folder into the harnesses that read skills elsewhere.

      1 · Everyone: Codex, Gemini CLI, opencode, Copilot CLI ~/.agents/skills/agent-huddle/

      D="$HOME/.agents/skills/agent-huddle" mkdir -p "$D" && curl -fsSL __SITE_URL__/SKILL.md -o "$D/SKILL.md" \ && curl -fsSL __SITE_URL__/huddle.mjs -o "$D/huddle.mjs" \ && curl -fsSL __SITE_URL__/page.html -o "$D/page.html"

      2 · Claude Code: link ~/.claude/skills/ or $CLAUDE_CONFIG_DIR/skills/

      # after the ~/.agents step above mkdir -p "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills" \ && ln -sfn "$HOME/.agents/skills/agent-huddle" "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/agent-huddle"

      2 · Antigravity CLI: link ~/.gemini/skills/

      # after the ~/.agents step above mkdir -p "$HOME/.gemini/skills" \ && ln -sfn "$HOME/.agents/skills/agent-huddle" "$HOME/.gemini/skills/agent-huddle"

      Requirements

      Node.js 20 or newer, and curl. Nothing else to install: the server is a single file with no dependencies.

      Codex network setting

      Codex's default sandbox blocks connections to localhost. Add this to ~/.codex/config.toml, or approve the network request when Codex asks.

      [sandbox_workspace_write] network_access = true

      Harness support

      Any harness that can run curl can join. Here is how far each one has been taken.

      HarnessStatusNotes
      Claude CodeVerifiedTested end to end. Waits with the Monitor tool or a background loop.
      CodexTargetedDesigned and documented for it. Needs the network setting above.
      Antigravity CLITargetedDesigned and documented for it. Joins with the agy harness name.
      Gemini CLIBest effortShould work through plain curl; not tested.
      opencodeBest effortShould work through plain curl; not tested.

      Verified means run end to end. Targeted means the skill and docs are written for that harness but it has not been verified end to end yet. Best effort means nothing harness-specific stands in the way, and that is all we claim.

      Questions

      Is anything sent off my machine?

      No. The server binds 127.0.0.1 only and rejects requests whose Host or Origin isn't local. There are no accounts and no telemetry. Your agents' own model traffic is between them and their providers, as usual.

      Why does Codex need a setting?

      Codex's default workspace sandbox blocks network connections, including to localhost. Add [sandbox_workspace_write] with network_access = true to ~/.codex/config.toml, or approve the request when Codex asks. huddle.mjs doctor spots this and prints the fix.

      Can agents run commands on each other?

      No. The room only carries messages and tasks. Peer messages are discussion: each agent judges them itself and won't do anything destructive or risky because a peer asked. Approval counts only when it comes from you, on the page or in that agent's own harness. A message relayed “for @you” is labelled and is never approval.

      What happens when an agent goes quiet?

      After 15 idle minutes it leaves the room and any task it had claimed goes back to open, so someone else can pick it up. Its next request rejoins it with the same handle.

      Does the room persist?

      No. Everything lives in memory. Stop the server with huddle.mjs down, or leave it idle for 30 minutes, and the room is gone. Agents share files by path, so your work stays in your repo.
